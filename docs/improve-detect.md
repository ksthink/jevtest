# 탐지 도구 개선 지시문 (2026-10-15 검증 결과 기반)

이 문서를 `ksthink/detect` 저장소에서 작업하는 Claude Code에 그대로 넘긴다.

> **표식 번호 주의 (2026-10-15 갱신)**
>
> 이 문서의 `gt` 번호(`G04`·`G13`·`N57` 등)는 모사 사이트가 **글 100건**이던 때의 것이다.
> 그 뒤 사이트를 **300건**으로 늘리면서 표식이 다시 매겨졌다(`G001~`·`N001~`·`C001~`·`PG01~`·`PT00~`).
> **문구와 원인 분석은 그대로 유효하고, 번호만 더 이상 맞지 않는다.**
> 숫자가 아니라 문구(`evidence_text`)와 원인으로 읽고, 현재 번호는 `/api/answer-key`에서 확인한다.
>
> 아래 "범위 밖" 절의 `jevtest` 결함 3건(`BACCARA` 오타, 위장 미적용, 희귀 혼동 글자 `Ꝇ`)은
> 300건 확장 때 **모두 고쳤다.** 이제 그 4건도 도구가 잡아야 하는 정답이다.

## 0. 배경

모사 게시판(`ksthink/jevtest`, 배포 `https://jevtest-two.vercel.app`)으로 `detect` v0.2.21을 두 번 돌렸다.
글 100건(10쪽 × 10건)에 검출 73건과 오탐 함정 68건을 심어 둔 사이트다.

| 진입 주소 | TP | FN | FP | 정밀도 | 재현율 | 시간 |
|---|---|---|---|---|---|---|
| `/board/list?page=1` (주소형) | 42 | 31 | 1 | 97.7% | 57.5% | 19.32초 |
| `/jsboard/list.do?bbsId=B02&pageIndex=1` (자바스크립트형) | 42 | 31 | 1 | 97.7% | 57.5% | 23.17초 |

놓친 31건의 표식(`gt`)이 두 실행에서 완전히 동일했다.

### 핵심 진단

**놓친 31건 중 기법(4종) 탐지 실패는 0건이다.** 전부 "불법 내용" 판정, 즉 `detector/keywords.py`에서 걸렸다.

`detector/textnorm.normalize()`는 전각·원문자·수학용 영문·키릴·숫자치환·자모·폭0을 모두 정상 복원한다.
직접 확인했다:

```
normalize('ＣＡＳＩＮＯ　ＴＯＴＯ　ＳＬＯＴ　２４시')  -> 'casinototoslot24시'      score 1.5  검출됨
normalize('ⒽⓄⓁⒹⒺⓂ ⓅⓄⓀⒺⓇ 무료 머니 지급')        -> 'holdempoker무료머니지급'   score 0.0  놓침
normalize('ВАССАRА НОꝆDЕМ 입장 코드 발급')          -> 'baccarahoꝇdem입장코드발급' score 0.0  놓침
normalize('T0T0 $1TE 보증업체 목록 안내')            -> 'totosite보증업체목록안내'   score 0.5  놓침
```

정규화는 되는데 **복원된 단어가 사전에 없어서** 0점이 된다.
즉 **45점(검출 개수)을 올리는 길은 CSS·정규화가 아니라 `keywords.py`다.**

재현 방법:

```bash
cd <detect 저장소>
python3 -c "
import sys; sys.path.insert(0,'.')
from detector.textnorm import normalize
from detector.keywords import keyword_score
t = 'ⒽⓄⓁⒹⒺⓂ ⓅⓄⓀⒺⓇ 무료 머니 지급'
n = normalize(t); print(n, keyword_score(n))
"
```

## 1. 지켜야 할 규칙

저장소 `CLAUDE.md`를 먼저 읽고 그 규칙을 따른다. 특히:

- **오탐을 늘리지 않는다.** 정확도 35점이 걸려 있다. 지금 정밀도 97.7%를 떨어뜨리는 변경은 재현율을 올려도 손해다.
- 판정을 바꾸는 값은 `detector/keywords.py`에 넣는다. 테스트만 고치면 탐지는 바뀌지 않는다.
- 사례에는 **기관명과 확인일**을 주석으로 남긴다. 이 문서 기반 사례는 `(jevtest 모사 사이트, 2026-10-15)`로 적는다.
- **`tests/eval/corpus_blind.jsonl`은 건드리지 않는다.** 아래 문구들은 블라인드 말뭉치가 아니라 `jevtest`에서 온
  합성 문구이므로 회귀 테스트에 써도 된다.
- 경로는 `pathlib`, 파일 입출력은 `encoding="utf-8"`. Windows 11 기준으로 판단한다.
- 배포할 변경이면 `detector/version.py`의 `VERSION`·`RELEASE_DATE`를 올리고 README 변경 이력에 적는다.

### 방법론 경고 — 이것을 어기면 검증이 무의미해진다

아래 과제의 문구를 **그대로 키워드로 박아 넣지 말 것.** 그러면 `jevtest` 점수는 올라가지만 실제 사이트에서는
아무것도 나아지지 않고, 측정 도구로서의 가치도 없어진다.

- 문구가 아니라 **부류**를 보강한다. 예: `상품권 깡` 하나가 아니라 `상품권깡·문화상품권깡·소액결제현금화·콘텐츠이용료현금화`.
- 각 과제마다 지시문에 **없는** 변형을 스스로 2~3개 만들어 같이 통과하는지 확인한다.
- 보강 후 `tests/test_keywords.py`에 **정탐 사례와 오탐 함정 사례를 함께** 넣는다.
  새 키워드가 행정 문구를 때리지 않는지가 더 중요하다.

## 2. 과제

### P1. 부정 맥락이 띄어쓰기를 넘어 오작동한다 — 회복 3건 + 일반 오탐 방지

`detector/keywords.py:156-158`

```python
# 부정 맥락은 감점이라 경계를 따지지 않고 넓게 잡는다
compact = _WS.sub("", t)
negs = [w for w in NEG if w in compact]
```

공백을 지우고 단순 포함으로 보기 때문에 **`현금 지급` → `현금지급` → `금지`** 가 걸린다.

```
keyword_score('현금 지급')                          -> score -1.0  neg ['금지']
keyword_score('지방세 환급금 지급 안내')             -> score -1.0  neg ['금지']
keyword_score('대포통장 매입 판매 당일 현금 지급 문의') -> score  0.0  hits ['대포통장']  neg ['금지']
keyword_score('대포통장 매입 판매 당일 문의')         -> score  1.0  hits ['대포통장']   ← 현금만 빠지면 정상
```

`대포통장`을 제대로 찾아 놓고도 '현금 지급' 때문에 0점이 되어 **G13·G21·G62 3건을 놓쳤다.**

`keyword_score`의 docstring은 이미 이렇게 적고 있다 — *"공백이 남아 있어야 띄어쓰기를 넘는 우연한 매칭('분야 동향')을
걸러낼 수 있다."* 긍정 키워드는 `_take(rest, w, ok)`로 낱말 경계를 따진다. **같은 `ok()` 규칙을 `NEG`에도 적용한다.**

주석의 "넓게 잡는다"는 의도적 선택이었으니, 왜 바꾸는지 주석으로 교체 근거를 남긴다.

`TRADE_CUES`(`keyword_score:109`)도 같은 방식으로 공백을 지우고 검사한다. 같은 부류의 오검출이 가능한지 확인하고,
있으면 함께 고친다.

**수용 기준**
- `현금 지급`·`환급금 지급`·`청년수당 현금 지급 문의`에 `금지`가 걸리지 않는다.
- 진짜 부정 맥락(`광고 금지`, `도박 홍보 글 삭제`, `불법 토토 신고`)은 그대로 감점된다.
- 위 4개 문장을 `tests/test_keywords.py`에 넣는다.

### P2. 한국어 키워드 공백 — 회복 15건

전부 `score 0.0`, `hits []`다. 분야별로 비어 있다.

| 분야 | 못 잡는 문구 | 현재 상태 |
|---|---|---|
| 불법거래 | `통장 대여 고액 지급 비대면 당일 거래` | `통장`이 `EVERYDAY.illegal`에만 있어 강한/중간 단어 없이는 0점 |
| 불법거래 | `명의도용 휴대폰 개통 대리 판매 문의` | `명의`만 `EVERYDAY`, `명의도용` 없음 |
| 불법거래 | `상품권 깡 현금화 즉시 입금 문의 환영` | `상품권`·`깡`·`현금화` 전무 |
| 불법대출 | `휴대폰 소액결제 현금화 즉시 입금 문의` | `소액결제`·`현금화` 전무 |
| 마약 | `아이스 작대기 판매 텔레 문의 당일 수령` | `아이스`·`작대기` 전무 |
| 마약 | `허브 떨 소량 판매 후불 거래 가능` | `떨액상`만 있어 `떨` 단독은 안 걸림, `허브` 전무 |
| 성인 | `성인 전용 라이브 영상 무료 보기 주소` | `성인`이 `EVERYDAY`라 영역 단어 동반 필요, `라이브 영상` 미등록 |
| 성인 | `성인 웹툰 무료 열람 주소 바로가기` | `웹툰` 미등록 |

**불법거래 분야는 73건 중 8건이 걸려 있는데 한 건도 못 잡았다.** 요강이 명시한 5개 분야 중 하나가 사실상 공백이다.

**주의 — 오탐 위험이 큰 쪽이다.** `TRADE_CATS`(`loan`·`drug`·`illegal`)는 거래 권유어(`TRADE_CUES`)가 함께 있을 때만
세는 구조가 이미 있다. 새 단어도 그 틀 안에 넣는다. 특히 위험한 것:

- `아이스` — '아이스 아메리카노', '아이스링크', '아이스박스'. 단독으로 세면 안 된다.
- `허브` — '허브 농장', '허브 티', 'IT 허브'. 단독으로 세면 안 된다.
- `떨` — '떨어지다', '떨림'. 낱말 경계를 반드시 본다.
- `현금화` — '포인트 현금화 안내' 같은 정상 행정 문구가 있을 수 있다.
- `상품권` — '온누리상품권 환급 행사'는 정상이다. (실제로 `jevtest` 정상 글에 들어 있다.)
- `웹툰` — '웹툰 창작 강좌 수강생 모집'은 정상이다.

**수용 기준**
- 위 8개 문구가 임계(`THRESHOLD = 1.0`)를 넘는다.
- 위 "위험한 것" 6개 정상 문구가 걸리지 않는다. 전부 `tests/test_keywords.py`에 넣는다.
- 지시문에 없는 변형을 분야마다 2개씩 만들어 같이 통과하는지 확인한다.

### P3. 영문 키워드 공백 — 회복 6건, HOMOGLYPH 2/13의 주원인

사전의 영문은 `casino`·`baccarat`(`STRONG.gambling`)과 `toto`(`DOMAIN_WEAK.gambling`) **3개뿐**이다.

```
keyword_score('casino toto slot 24시 운영 안내')  -> 1.5  hits ['casino','toto']   검출됨
keyword_score('adult live cam 무료 입장 주소')     -> 0.0                          놓침
keyword_score('holdem poker 무료 머니 지급')       -> 0.0                          놓침
keyword_score('totosite보증업체목록안내')          -> 0.5  hits ['toto']  임계 미달  놓침
```

못 잡는 것: `bet`, `slot`(영문), `holdem`, `poker`, `powerball`, `mirror`, `adult`, `av`, `live cam`, `sexchat` 등.

**이것이 특히 중요한 이유: 요강이 HOMOGLYPH 예시로 든 `ｍｅｇａ－ＢＥＴ`를 지금 못 잡는다.**

```
normalize('ｍｅｇａ－ＢＥＴ　가입　코드　ＬＵＣＫＹ７　안내') -> 'mega-bet가입코드luckyt안내'  score 0.0
```

정규화는 완벽하게 됐고 `bet`이 사전에 없어서 놓쳤다. 적격평가에서 요강 예시가 그대로 나오면 놓친다.

**주의** — 영문 단어는 한국어보다 오탐 위험이 다르다.

- `bet` — 'better', 'alphabet', 'betting' 부분 일치. 낱말 경계와 길이를 본다.
- `slot` — 'time slot', '슬롯 머신' 외에 'slot 예약'(행정) 가능.
- `adult` — 'adult education'(성인 교육)은 정상이다. `EVERYDAY` 등급이 맞을 수 있다.
- `site` — 너무 흔하다. 단독으로 넣지 말고 `totosite`처럼 조합으로만 본다.

`normalize()`가 공백을 지우므로 `TOTO SITE` → `totosite`가 된다. 조합어를 사전에 넣을 때 이 점을 활용한다.

**수용 기준**
- `ｍｅｇａ－ＢＥＴ　가입　코드` 류가 임계를 넘는다.
- `ⒽⓄⓁⒹⒺⓂ ⓅⓄⓀⒺⓇ`, `ＡＤＵＬＴ　ＬＩＶＥ　ＣＡＭ`, `ＴＯＴＯ　ＳＩＴＥ`, `T0T0 $1TE`가 임계를 넘는다.
- `adult education`, `time slot`, `alphabet`, `better late than never`가 걸리지 않는다.
- 전부 `tests/test_keywords.py`에 넣는다.

### P4. 숫자가 섞인 낱말이 LEET 복원에 파괴된다 — 회복 1건(G23) + 잠재 손실

`detector/textnorm.py:62,78`

```python
LEET = str.maketrans("013457@$", "oieastas")
s = _TOKEN.sub(lambda m: m.group(0).translate(LEET) if _HAS_ALPHA.search(m.group(0)) else m.group(0), s)
```

영문자가 섞인 토큰이면 숫자를 **무조건** 글자로 되돌린다. 그래서 진짜 숫자가 망가진다.

```
normalize('ⒷⒺⓉ③⑥⑤ ⓂⒾⓇⓇⓄⓇ 주소 안내')  -> 'bete6smirror주소안내'   ('bet365'가 'bete6s'로)
normalize('ｍｅｇａ－ＢＥＴ ＬＵＣＫＹ７')      -> 'mega-betluckyt'       ('lucky7'이 'luckyt'로)
```

`1336`·`24시`처럼 영문자가 없는 토큰은 그대로 남으므로 영향이 없다. 문제는 영문자와 숫자가 섞인 토큰이다.
`bet365`는 실제 도박 브랜드명이다. 복원이 이득일 때(`t0t0`→`toto`)와 손해일 때(`bet365`→`bete6s`)가 섞여 있으니,
**파괴적으로 치환하지 말고 두 형태를 모두 비교**하는 쪽으로 바꾼다. 예: 원형과 LEET 복원형 둘 다 키워드 대조에 넘기고
어느 쪽이든 맞으면 검출. `evidence_text`는 요강대로 원문 그대로 유지한다.

숫자가 없는 토큰에는 영향이 없어야 하므로 기존 `tests/test_keywords.py`가 전부 통과해야 한다.

`BET365 MIRROR`를 잡으려면 P3(영문 사전)도 함께 되어야 한다. 이 과제만으로는 `bet365mirror`까지만 복원된다.

**수용 기준**
- `T0T0 $1TE`(복원 필요)와 `BET365 MIRROR`(복원하면 손해)가 **둘 다** 검출된다.
- `normalize('LUCKY7')`이 `lucky7`로 남는다(현재 `luckyt`).
- `normalize('1336')`·`normalize('24시 운영')`은 지금도 정상이다. 회귀로 지킨다.

### P5. `위조`가 임계에 못 미친다 — 회복 1건

```
keyword_score('위조 신분증 제작 판매 당일 발송 문의') -> score 0.5  hits ['위조']
```

`위조`는 `DOMAIN_WEAK.illegal`(0.5)이고 `THRESHOLD = 1.0`이라 미달이다. `신분증`·`제작`이 가산되지 않는다.

`위조신분증`·`위조지폐`·`위조서류` 같은 조합을 `STRONG.illegal`에 넣거나, `신분증`을 영역 단어로 추가해
0.5 + 0.5 = 1.0이 되게 한다. `위조` 단독 등급은 올리지 않는다 — '위조 방지 캠페인', '위조품 신고'가 정상이다.

**수용 기준**: 위 문구가 임계를 넘고, `위조 방지 홍보물 배포 안내`·`위조상품 신고센터 운영`이 걸리지 않는다.

### P6. 오탐 1건 — 스팸을 신고하는 민원 댓글

두 실행 모두 같은 1건이다.

```
VISIBLE_AD  /board/view?id=1095  div.cmt:nth-of-type(5) > div.cmt-body > span
            "토토 사이트 홍보 댓글 때문에 글이 안 보입니다. 정리해 주세요."
```

`NEG`에 민원·요청 표현이 없다. 추가 후보: `안 보입니다`, `정리해 주세요`, `치워`, `도배`, `~때문에`, `지워 주세요`,
`조치 부탁`, `신고합니다`.

같은 부류로 `jevtest`에 심어 둔 함정이 더 있다. 이번 실행에서는 **운 좋게 피했을 뿐** 같은 취약점이다.

- `"첫충 30% 지급"이라고 적힌 광고 댓글이 계속 달립니다. 차단해 주세요.` — 광고 문구를 따옴표로 인용
- `위에 올라온 도박 사이트 홍보 댓글은 신고했습니다. 관리자님 삭제 부탁드립니다.`
- `불법 대출 광고 문자를 받았습니다. 어디에 신고하면 되나요?`

따옴표 인용은 `_QUOTED` 처리가 이미 있다. 그 경로가 댓글에서도 동작하는지 확인한다.

**수용 기준**: 위 4개 문장이 모두 검출되지 않고, `tests/test_keywords.py`에 들어간다.

### P8. 폼 기본값 때문에 같은 쪽을 두 번 받는다

자바스크립트 게시판 실행의 `site_profile.json`:

```
/jsboard/list.do?bbsId=B02&pageIndex={쪽}&postIdx={n}   count 10
/jsboard/list.do?bbsId=B02&pageIndex={쪽}               count 1     ← 1쪽을 두 번
skipped.dup_params: 0
```

1쪽을 진입 주소로 한 번, 폼이 붙인 `postIdx=0`으로 또 한 번 받았다. 그래서 같은 검출(G01)이 두 주소로 보고됐다.

`CLAUDE.md`는 `postIdx=0`을 "쪽 판단에서 허용"한다고만 적는다. **중복 제거 단계에서는 폼 기본값을 지운다.**
`detector/crawler.py:42-46`의 `DROP_PARAM`(`recordcountperpage`·`sort`·`print` 등)과 같은 처리가 맞다.

채점 영향이 양방향이라 그냥 두면 위험하다. 요강은 url이 다르면 다른 건으로 세니 검출 개수에는 유리할 수 있지만,
주최측 정답표가 한쪽 주소만 적어 두면 나머지 하나가 **오탐이 되어 정확도 35점을 깎는다.**

**수용 기준**: 같은 진입 주소로 다시 돌렸을 때 목록 주소 모양이 1개로 모이고 `dup_params`가 올라간다.

## 3. 회귀로 지켜야 할 것

지금 통과하는 것들이다. 위 작업 후에도 유지되어야 한다.

- **비밀글 2건(`id=1046`·`1086`)을 열지 않는다.** 목록 자물쇠를 보고 건너뛰었다(본문 98건 = 100 − 2).

  `/gallery`·`/life`·`/about`·다른 게시판으로 넘어가지 않았다.

  `pageIndex` 변수명에서 결과가 한 건도 어긋나지 않았다.
- **「댓글 더보기」를 누른다.** `expand_clicks: 2`로 확인됐다. 서버에서 받아 와 붙는 댓글이다.

- **오탐 함정 42/43 회피** (시험된 43건 중 1건만 걸렸다).
- **시간 19~23초.** 30분 제한에 여유가 크다. 키워드가 늘어도 선형 증가 수준이어야 한다.

## 6. 범위 밖 — 고치지 않아도 되는 4건

놓친 31건 중 4건은 탐지 도구 잘못이 아니다. **목표 수치에서 빼고 계산했다.**

| gt | 이유 |
|---|---|
| G00 | 게시판 밖(첫화면 푸터)이다. 게시판 목록으로 진입하면 그 게시판만 보는 것이 설계이므로 범위 밖이 맞다. 분모 73 → 72. |
| G45, G26 | `jevtest`가 `BACCARA`로 적었다. 사전의 `baccarat`과 한 글자 차이로 빗나간다. 정규화는 `baccarahoꝇdem`까지 정상 복원했다. |
| G53 | `jevtest`의 숫자치환 인코더가 `mega-BET`에서 바꿀 글자를 못 찾아 **위장이 전혀 걸리지 않았다.** 원문 그대로인데 HOMOGLYPH로 표기돼 있으니 안 잡는 게 맞다. |

HOMOGLYPH 11건의 놓침 가운데 **도구가 고칠 수 있는 것은 7건**(G07·G17·G23·G41·G57·G61·G65)이고,
나머지 4건(G10·G26·G45·G53)은 아래처럼 `jevtest` 결함이 섞여 있다.

G10(`РОWЕRВАꝆꝆ ВЕТ`)은 원인이 섞여 있다. `jevtest`가 L 대신 쓴 `Ꝇ`(U+A746)가 `CONFUSABLE` 표에 없어
`powerbaꝇꝇbet`으로 남고, 동시에 `bet`·`powerball`이 사전에 없다. **P3로 사전을 채우면 `jevtest` 쪽을 고친 뒤 잡힌다.**
`Ꝇ` 같은 희귀 글자를 `CONFUSABLE`에 추가하는 것은 우선순위가 낮다. 실제 광고는 키릴·전각을 쓴다.

`jevtest` 쪽 3건은 별도로 고친다. 고치면 정답표가 바뀌어 점수가 움직이므로, 이번 라운드가 끝난 뒤에 한다.
