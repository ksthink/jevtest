# 공공기관 게시판 모사 테스트 사이트

불법광고 탐지 도구를 검증하려고 만든 **가상 공공기관 누리집**입니다.
공공기관 게시판을 흉내 낸 글 **500건(50쪽 × 10건)** 가운데 일부에 위장·은닉한 가짜 광고를 심어 두고,
어디에 무엇을 심었는지 **정답표**로 함께 내려 줍니다.

- 외부에서 바로 접속할 수 있습니다(로그인·인증 없음).
- **데이터베이스가 없습니다.** 글 500건은 코드 안에 고정되어 있어 배포해도 매번 같은 사이트가 나옵니다.
- **의존성이 하나도 없습니다.** `npm install`도 빌드도 없이 버셀에 그대로 올라갑니다.

> 심어 둔 광고 문구·연락처·주소는 모두 가짜입니다. 실제 기관·업체와 관련이 없습니다.
> 모든 페이지에 `noindex`가 걸려 있어 검색엔진에 올라가지 않습니다.

---

## 1. 띄우기

### 로컬

```bash
node server.js            # http://localhost:3000
PORT=8080 node server.js
```

Node 18 이상이면 됩니다(설치할 것 없음).

### 버셀 배포

```bash
npm i -g vercel
vercel          # 미리보기
vercel --prod   # 운영
```

`vercel.json`이 모든 주소를 서버리스 함수 `api/index.js` 하나로 보냅니다.
깃허브 저장소를 버셀에 연결해도 그대로 동작합니다(프레임워크 선택: **Other**, 빌드 명령 없음).

배포가 끝나면 받은 주소를 그대로 탐지 도구에 넣습니다.

```bash
detect.exe https://<배포주소>/board/list?page=1
```

## 2. 주소 구성

| 주소 | 내용 |
|---|---|
| `/` | 첫화면. 쪽 넘김이 없는 '최근 게시물' 목록이 있어 게시판으로 오인하면 안 된다. 푸터에 숨긴 광고 1건 |
| `/board/list?page=1` ~ `50` | **열린게시판.** 일반 주소형 쪽 넘김. 쪽 번호 변수는 `page` |
| `/board/view?id=1001` ~ `1500` | 글 상세. 본문·댓글·iframe |
| `/jsboard/list.do?bbsId=B02&pageIndex=1` | **자유게시판.** 글 링크와 쪽 넘김이 모두 자바스크립트(`fn_view`, `fn_egov_link_page`). 쪽 번호 변수는 `pageIndex`, 시작 주소에만 있는 값 `postIdx=0`이 섞여 있다 |
| `/jsboard/view.do?nttId=1001` | 같은 글을 다른 주소로 보여 주는 상세 |
| `/gallery?page=1` | **포토갤러리.** 표가 아닌 카드형 목록 |
| `/life` | 오탐 함정 모음(접힌 메뉴·탭·아코디언·팝업·슬라이더, 보도·법령·행정 문구) |
| `/about` | 기관 소개. 게시판이 아닌 일반 페이지 |
| `/iframe/ad?id=<글번호>` | 글 안의 iframe 문서 |
| `/api/comments?id=<글번호>` | 「댓글 더보기」를 눌렀을 때 받아 가는 댓글 조각 |
| `/answer-key` | 정답표 화면 |
| `/api/answer-key` | 정답표 JSON (`?format=flat`, `?origin=https://...`) |
| `/robots.txt` | 전부 허용(`--respect-robots`로 돌려도 막히지 않게) |

### 게시판별로 무엇을 보는가

| 게시판 | 확인하려는 것 |
|---|---|
| 열린게시판 | 주소형 쪽 넘김, 쪽 구간 선택(`--pages 3-15`), 목록 → 상세 따라가기 |
| 자유게시판 | `javascript:` 글 링크와 `onclick`, 폼으로 보내는 쪽 넘김, 쪽 번호 변수 이름이 다른 경우 |
| 포토갤러리 | 목록 행이 표가 아니어도 게시판으로 인식하는지 |
| 첫화면 | 쪽 넘김 없는 목록을 게시판으로 오인하지 않는지, 게시판 밖 페이지도 훑는지 |
| 비밀글 10건(`id=1048`·`1089`·`1135`·`1190`·`1232`·`1277`·`1319`·`1366`·`1413`·`1469`) | 열지 않거나, 열었을 때 "내용 확인 불가"로 처리하는지 |
| 정상 iframe (`/iframe/ad?id=0`) | iframe이 있다는 이유만으로 검출하지 않는지 |
| 댓글 | 상세 페이지의 댓글 영역까지 읽는지 |
| 댓글 더보기 14건 | 더보기를 눌러 펼친 뒤 분석하는지. 삭제·신고·작성 버튼은 누르지 않아야 한다 |

### 수집·정제 도구 (`tools/harvest.mjs`)

새 사례를 모았을 때 쓰는 도구입니다. 수집한 원문에는 **진짜 도메인과 텔레그램 핸들이 그대로** 들어 있고,
소스코드가 제출물이라 그대로 넣으면 안 됩니다. 이 도구가 기계적으로 막습니다.

```bash
node tools/harvest.mjs --file raw.txt     # 정제 + 분야 추정 후 copy.js 에 붙일 줄로 출력
node tools/harvest.mjs --file raw.txt --json
```

- **식별자 치환**: URL·도메인(한글 도메인 포함)·텔레그램 핸들·카톡 ID·전화번호를
  `ad-test01.example.test`·`TGTEST01`·`000-0000-0000` 으로 바꿉니다. 같은 값은 같은 가짜로 갑니다.
- **분야 추정**: 키워드로 8개 분야 중 하나를 고르고, 확신이 없으면 `UNKNOWN`으로 남깁니다.
- **거르기**: 너무 짧거나 한글이 없는 줄은 버립니다.

분류는 추정이므로 붙이기 전에 사람이 한 번 봅니다.

### 겹치기·분야

- 한 요소에 **기법이 겹친** 경우 1건(`opacity:0` + `font-size:0`) → 기법별로 따로 1건씩 세야 합니다.
- 한 글에 **검출이 2건** 들어간 경우가 3건 있습니다.
- `HTML 엔티티`로 한 번 더 감싼 경우 1건(`&#49888;…` + `display:none`).
- 분야는 요강의 5개(**도박·성인·불법대출·마약·불법거래**)를 모두 덮습니다.
- 쪽마다 검출이 고르게 퍼져 있어 쪽 구간 선택이나 중복 합치기를 시험할 수 있습니다.

## 4. 정답표

페이지 HTML의 **`data-gt` 속성이 채점 표식**입니다. 탐지 판정에 쓰면 안 됩니다.

```html
<p data-gt="G025" style="opacity:0;font-size:0">카지노 신규가입 첫충 30% 머니 지급</p>
```

표식 접두어는 이렇게 나눕니다.

| 접두어 | 뜻 |
|---|---|
| `G001` ~ | 글에 심은 검출 (제목·본문·댓글·iframe) |
| `N001` ~ | 글 본문의 오탐 함정 |
| `C001` ~ | 댓글의 오탐 함정 |
| `PG01` ~ | 게시판 밖 페이지에 심은 검출 |
| `PT00` ~ | 게시판 밖 페이지의 오탐 함정 |

`/api/answer-key`는 이렇게 생겼습니다.

```json
{
  "counts": { "posts": 500, "pages": 50, "unique_findings": 365, "traps": 174,
              "by_code": { "HOMOGLYPH": 69, "JAMO": 39, "TRANSPARENT": 87, "OFFSCREEN": 105, "…": 0 },
              "by_scope": { "spec": 305, "extra": 60 } },
  "expected_findings": [
    { "gt": "G007", "bucket": "main", "code": "OFFSCREEN",
      "url": "https://<배포주소>/board/view?id=1007",
      "location": "iframe[src=\"https://<배포주소>/iframe/ad?id=1007\"] >>> [data-gt=\"G007\"]",
      "evidence_text": "…",
      "post_id": 1007, "where": "iframe", "via": null, "note": "화면 밖: display:none" },
    { "gt": "G004", "bucket": "main", "code": "HOMOGLYPH",
      "url": "https://<배포주소>/board/view?id=1005",
      "location": "[data-gt=\"G004\"]",
      "evidence_text": "ⓅⓄⓌⒺⓇⒷⒶⓁⓁ ⒷⒺⓉ 실시간 중계 주소",
      "post_id": 1005, "where": "comment", "via": "comment-more",
      "note": "닮은꼴: 원문자 / '댓글 더보기'를 눌러야 나타남" }
  ],
  "expected_absent": [
    { "gt": "PT11", "url": "https://<배포주소>/life", "location": "[data-gt=\"PT11\"]",
      "text": "도박 중독이 의심되면 국번 없이 1336으로 상담하세요.",
      "hidden": true, "post_id": 0, "via": null, "note": "접힌 아코디언, 부정 맥락" }

```

- `bucket: "main"`은 `result.json`에, `"extra"`는 `result_extra.json`에 있어야 합니다.
- 같은 삽입이 여러 주소에 보이면(제목은 목록 3곳 + 상세 2곳) 주소마다 한 줄씩 들어갑니다.
  채점은 `gt` 단위로 하면 됩니다.
- 사이트를 다른 주소로 띄워 검사했다면 `?origin=https://...`로 주소를 맞출 수 있습니다.
- `via: "comment-more"`인 건은 **처음 HTML에 없습니다.** 「댓글 더보기」를 누르지 않는 도구는
  이 2건을 놓치는 것이 정상입니다(놓쳐도 다른 71건에는 영향이 없습니다).

## 5. 채점

탐지 도구가 만든 `result.json` / `result_extra.json`을 정답표와 맞춰 봅니다.

```bash
node tools/score.mjs --site https://<배포주소> \
  --result ./result.json --extra ./result_extra.json
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--site` | `http://localhost:3000` | 검사한 사이트 주소 |
| `--result` | `./result.json` | 적격평가 4종 결과 |
| `--extra` | `./result_extra.json` | 추가 유형 결과 |
| `--answer-key` | `<site>/api/answer-key` | 정답표 주소. 검사한 사이트에 직접 닿을 수 없을 때 다른 데서 받아 온다 |

```bash
# 사이트에 닿을 수 없는 곳에서 채점할 때 (정답표만 로컬 서버에서 받는다)
node tools/score.mjs --site https://<배포주소> \
  --answer-key "http://localhost:3000/api/answer-key?origin=https://<배포주소>"
```


대조 순서는 이렇습니다.

1. 보고된 `location`에서 `data-gt` 표식을 읽어 `gt`를 찾는다.
2. 표식이 없으면 **주소 + `evidence_text` + 기법**이 같은 정답을 찾는다(도구가 자기 선택자로 적어도 맞춰진다).
3. 그래도 없으면 `evidence_text` + 기법으로 찾는다.
4. `gt` + 기법이 맞으면 TP, 정답표에 없으면 FP, 못 찾은 정답은 FN.

2)에서 주소를 함께 보는 것이 중요합니다. 같은 광고 문구를 여러 글에 심어 두었기 때문에,
원문만으로 맞추면 서로 다른 글의 검출이 한 정답에 몰려 멀쩡한 검출이 오탐으로 깎입니다.

주소를 비교할 때는 경로마다 그 페이지를 가리키는 변수만 남깁니다. 글 상세의 `page`처럼
화면 표시만 바꾸는 변수는 지웁니다(`?id=1045&page=5`와 `?id=1045`는 같은 글입니다).
`extra_finding`에 `ZERO_WIDTH(폭 0 문자 삽입)`처럼 설명이 붙어 있어도 앞쪽 코드만 떼어 맞춥니다.
NFD 자모 분해처럼 눈에 안 보이는 표기 차이도 흡수합니다.

같은 정답을 두 주소로 보고한 것은 오탐이 아니라 **중복**으로 따로 셉니다(제목 검출은 목록과
상세 양쪽에 보이므로 정상입니다). 요강은 (url + location + technique)을 1건으로 세므로
중복으로 집계된 건도 요강 기준으로는 별건으로 인정됩니다.

### 심는 것을 바꾸려면

`data/posts.js`가 배치를 **생성**합니다. 쪽마다 글 10건 가운데 앞 7자리에 검출을, 뒤 3자리에 함정을 두고,
자리는 쪽마다 돌려서 모든 쪽이 똑같은 모양이 되지 않게 합니다.

```js
// data/posts.js
const SLOT_ORDER = [0, 1, 3, 4, 6, 7, 9, 2, 5, 8];   // 앞 7개 검출, 뒤 3개 함정
const FINDING_SLOTS = 7;
const SLOT_WHERE = ['title', 'body', 'comment', 'body', 'comment', 'comment', 'iframe'];
const SECRET = new Set([47, 88, 134, /* … */ 468]);   // 비밀글(아무것도 심지 않는다)
```

- **기법·변형을 늘리려면** `HOMOGLYPH_V`·`JAMO_V`·`TRANSPARENT_V`·`OFFSCREEN_V`에 줄을 더합니다.
  `VARIANTS`가 자동으로 다시 계산되고 배치에 섞여 들어갑니다.
- **광고 문구를 늘리려면** `data/copy.js`의 `AD_COPY`(한글)와 `AD_COPY_LATIN`(라틴 키워드)에 줄을 더합니다.
- **함정을 늘리려면** `TRAP_LINES`(본문)와 `TRAP_COMMENTS`(댓글)에 줄을 더합니다.
  본문 함정 자리가 쪽마다 2개, 댓글 함정이 1개이므로 50쪽에서 각각 100·50줄까지 씁니다.
- **글 수를 바꾸려면** `TOTAL_POSTS`만 고칩니다. 쪽 수는 자동으로 따라옵니다.

고친 뒤 `node tools/check.mjs`로 확인하면 정답표가 자동으로 따라옵니다.

### 위장이 안 걸리면 만들 때 막습니다

`build()`는 글자를 바꾸는 기법(`HOMOGLYPH`·`JAMO`·`ZERO_WIDTH`)에서 **결과가 원문과 같으면 예외를 던집니다.**

```
Error: G009: JAMO 인데 위장이 걸리지 않았다 -> "스포츠 배팅 안전주소 매일 변경 공지"
```

위장이 안 걸린 문구를 정답표에 "위장했다"고 적으면 탐지 도구가 맞게 판단해도 틀린 것으로 채점됩니다.
문구를 더할 때 이 예외가 나면 그 문구나 인코더를 고쳐야 합니다.
